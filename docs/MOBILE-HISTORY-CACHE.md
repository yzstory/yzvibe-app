# 手机会话历史缓存

- iOS、Android 均先展示已有消息；同一连接期间再次进入已同步会话不重复拉取整段历史。
- 两端的本地缓存按设备 ID + 会话 ID 隔离，放在系统缓存目录，预算各 100 MB，按访问时间淘汰。系统清理缓存后可从连接器恢复。
- iOS 用 actor，Android 用 IO dispatcher 处理 JSON 和磁盘操作；流式消息最多约每秒合并写入一次，不逐 token 写文件。缓存故障不影响通信；草稿、发送队列仍使用原有持久化。
- App 重启/断线后，先显示可用缓存，再请求当前会话的权威快照。未打开的会话延后到进入时同步，避免重连同时读取所有已访问会话。保留全量校准是为了同步旧消息中的工具结果修改，而不只是追加新消息。
- iOS 初始渲染最近 80 条消息，上方按钮每次展示更早 80 条；阅读历史时新消息不会挤掉窗口开头。Markdown 解析结果另有有界内存缓存，主题、文字大小、内容变化会使用新的缓存项。
- 此优化不改变模型输入上下文，不增加模型 token 调用。100 MB 是历史文件预算，不代表 App 的总内存/磁盘占用；图片和视频仍沿用原有加载方式。

验证：iOS 缓存重建、设备隔离、损坏回退、预算淘汰、先缓存后联网、重复进入、重连按需刷新；Android 缓存重建/隔离/损坏/预算测试及构建、lint。
