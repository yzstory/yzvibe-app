## 当前边界

- 不确定的写请求不会自动重试；这避免本轮引入重复执行，不等同于已经实现端到端幂等发送。requestId 与持久化待发送箱仍属于后续工作。
- 重连采用完整快照保证旧消息更新，长会话后续可以用 revision / 事件游标减少传输。
- 会话 diff 的基线是起始 commit，因此仍可能包含会话开始前的未提交修改；它表达“基线以来的仓库差异”，不是严格的 Agent 改动归因。
- 路径保护覆盖静态符号链接和已知敏感路径，不宣称能隔离拥有相同本机账户权限、并发恶意替换文件系统的进程。
- 本次没有新增 Android、小程序、交付卡或任务级 worktree，也没有迁移整个项目到 Swift 6 语言模式。

## 值得做的拓展

| 顺序 | 内容 | 用户价值 | 前置条件 / 验收方式 |
| --- | --- | --- | --- |
| 1 | 任务完成摘要与交付卡 | 离开电脑后能快速看懂改了什么、测试是否通过、产物在哪 | 修好 diff；卡片能追溯到具体文件和工具结果，不凭模型描述断言测试通过 |
| 2 | 可靠的待发送箱 | 断网也能写指令，回来后能确认哪条已接收、失败或待重试 | 请求幂等性、队列持久化、明确的发送状态 |
| 3 | 连接诊断页与一键诊断导出 | 区分电脑离线、地址失效、Agent 登录异常和推送配置问题 | 诊断包默认移除 Token、密钥与会话正文；覆盖当前网络 / Agent / APNs 链路 |
| 4 | 任务级 worktree 隔离 | 同一仓库多个会话减少互相覆盖，改动可准确归因 | 展示所属分支 / 目录；结束时可查看、保留或清理工作区，合并需要明确操作 |
| 5 | 常用任务模板 | 手机少打字，快速启动代码检查、修复问题、生成测试等任务 | 复用现有命令 / Skill 面板；模板明确目录、模式和输入，默认不启用 Trust |
| 6 | Live Activity 生命周期完善 | App 重启后接回已有活动，失败状态更清楚 | 恢复系统已有活动，避免重复活动；分别验证前台、挂起、重启与推送结束 |

Android / 小程序可以继续保留路线图，但建议等真实网络集成测试、协议幂等性和错误语义稳定后再扩展客户端。
